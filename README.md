# Instrument Card AI

## Установка и запуск

Нужны Python 3.11+ и ключ OpenRouter. Выполните из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите ключ и модель с поддержкой JSON Schema:

```dotenv
OPENROUTER_API_KEY=your-openrouter-api-key
OPENROUTER_MODEL=nvidia/nemotron-3.5-super-vl:free
```

Запустите приложение:

```bash
python -m uvicorn src.main:app --reload
```

Откройте [localhost:8000](http://127.0.0.1:8000/), заполните данные прибора
и нажмите «Создать карточку». Результат можно скопировать в Markdown или JSON.
Документация API доступна на [/docs](http://127.0.0.1:8000/docs).
Генерация расходует лимит провайдера. Ключ хранится в `.env`, который исключён из Git.

## Промпты и принятые решения

В [src/prompts.py](src/prompts.py) системный промпт задаёт состав карточки,
ограничения длины и запрет на неподтверждённые сведения. Пользовательский промпт
содержит данные товара в JSON. Условия продажи, услуги магазина и характеристики
нельзя добавлять, если их нет во входе.

Модель возвращает текст и ключи выбранных характеристик. Значения характеристик
приложение берёт из исходного `specs`, неизвестные ключи отклоняет. Пустые значения
помечаются как «данных нет», а пропуски перечисляются в `missing_fields`.

FastAPI принимает запросы, Pydantic проверяет вход и ответ модели.
Для обращения к OpenRouter используется SDK OpenAI. Таймаут — 60 секунд,
автоматические повторы отключены, чтобы не тратить дополнительные запросы.

## Ограничения и возможные улучшения

- Проверка схемы не гарантирует достоверность текста. Даже с ограничениями в промпте модель может ошибаться.
- При небольшом количестве данных требование 800–1200 символов может привести к повторам или ошибке валидации.
- Результаты не сохраняются на сервере, каждый товар обрабатывается отдельно.

Можно добавить проверку технических утверждений и уникальности поисковых запросов,
сохранение карточек и обработку нескольких товаров за один запуск.
